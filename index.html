THE PRODUCT THESIS

A chat response is not an engineering state.

When planning, authority, mutation, verification, and recovery collapse into one conversation, fluent output can impersonate finished work. MAYA separates those responsibilities into inspectable product states.

01 / FAILURE MODE

Apparent progress

Generated narration can look complete while the repository is stale, checks were skipped, authority drifted, or no recoverable state exists.

02 / MECHANISM

Mission state

The objective, working context, plan, decisions, artifacts, receipts, blockers, and recovery paths remain distinct and visible.

03 / OPERATOR OUTCOME

Reviewable change

The operator can understand what happened, what remains uncertain, and whether the result deserves acceptance.

MISSION WORKFLOW

Every phase has an exit condition.

A phase is not finished because time passed or a model sounded confident. It ends when the operator can inspect the state required to move forward.

  1. 01

    Frame

    Define the objective, context, exclusions, intended outcome, and completion standard.

    EXIT / BOUNDED SCOPE
  2. 02

    Observe

    Separate acquired repository and runtime facts from assumptions and unavailable inputs.

    EXIT / CONTEXT VISIBLE
  3. 03

    Plan

    Review the proposed sequence, risk, authority needs, expected evidence, and rollback implications.

    EXIT / COURSE INSPECTABLE
  4. 04

    Authorize

    Approve or reject consequential actions at the narrowest useful boundary.

    EXIT / AUTHORITY BOUND
  5. 05

    Execute

    Follow bounded work through canonical states without replacing receipts with animation.

    EXIT / ACTIONS TERMINAL
  6. 06

    Verify

    Inspect changes, checks, artifacts, warnings, skipped work, and remaining uncertainty.

    EXIT / EVIDENCE SUFFICIENT
  7. 07

    Recover

    Retry, change strategy, branch from a checkpoint, or restore a known prior state.

    EXIT / HISTORY PRESERVED
